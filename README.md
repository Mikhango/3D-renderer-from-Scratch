# 3D Renderer from Scratch

Программный 3D-рендерер на C++20: вычисления и растеризация выполняются на CPU,
Eigen используется для линейной алгебры, Qt — для окон и ввода. Ядро собирается
в отдельную библиотеку `renderer_core` без зависимости от Qt.

## Возможности

- Преобразования model → view → clip → screen; пакетная обработка вершин Eigen.
- Отсечение по всем шести плоскостям, удаление обратных граней, барицентрическая
  растеризация с перспективно-корректной интерполяцией и z-буфером.
- Освещение Блинна–Фонга: фоновое, направленное и точечное; RGB-интенсивности.
- Тени от геометрии сцены: проверка лучей с ускорением BVH; переключатель теней.
- Цвет и прозрачность объекта; прозрачные фрагменты смешиваются от дальних к ближним.
- Режимы Shaded, Depth, Normals; настройка вертикального угла обзора.
- Загрузка OBJ: позиции, нормали, проверка индексов текстурных координат,
  отрицательные индексы, триангуляция простых выпуклых и вогнутых полигонов.
- Два окна: сцена и настройки; FPS, положение камеры, сообщения об операциях.
- Стартовая сцена: сфера, параллелепипед, пирамида и направленный свет.

## Управление

| Действие | Управление |
|---|---|
| Включить управление камерой | Активировать окно рендера; WASD работает без кнопок мыши |
| Освободить курсор | Курсор всегда видим и свободен; ЛКМ запускает только перетаскивание |
| Перемещение | WASD (или ЦФЫВ) в окне рендера независимо от ЛКМ; W/S вдоль текущего направления взгляда, включая наклон вверх/вниз, A/D вдоль локальной правой оси |
| Загрузить OBJ | Кнопка Load OBJ в Settings, Operations → Load object или `1` и Enter |
| Добавить фигуру | Кнопки Add Cube / Add Sphere / Add Pyramid в Settings; координаты и размеры в форме |
| Добавить направленный свет | Operations → Add light или `2` и Enter |
| Завершить приложение | Operations → Exit или `3` и Enter |
| Удалить объект | В окне Settings выбрать строку в списке Objects и нажать Remove selected object; удаляется только выбранный экземпляр |
| Свет от камеры | Y (Н в русской раскладке) в окне рендера: включить / выключить белый точечный свет в позиции камеры |


Объекты в списке имеют отдельные номера `#ID`, даже при загрузке одного файла несколько раз. После удаления нужно явно выбрать следующий объект. Полный путь виден во всплывающей подсказке строки. Свет камеры по умолчанию выключен; его состояние показано в Settings. Он следует за камерой, дополняет остальные источники и использует обычное затухание и тени точечного света.

Для OBJ нажмите **Load OBJ** в Settings и укажите путь. Затем открывается одна форма с X/Y/Z, поворотом, цветом RGB (целые 0…255) и opacity (0…1); отдельного вопроса о включении преобразования больше нет.

Кнопки **Add Cube**, **Add Sphere**, **Add Pyramid** создают фигуры без файлов. В форме задаются длина ребра куба, радиус шара либо сторона основания и высота пирамиды. X направлен вправо, Y вверх, Z задаёт глубину. Для куба и шара X/Y/Z — мировой центр; для пирамиды — центр основания. Для OBJ это мировой перенос относительно координат файла, без автоматического центрирования. Нулевые координаты оставляют исходное положение; угол задаётся в градусах, стандартная ось вращения — (0, 1, 0). Нажмите **Add object**, чтобы добавить фигуру, или Cancel для отмены.

Направление света
задаётся **от поверхности к источнику**. Точечный источник задаётся мировой
позицией; интенсивность каждого канала — 0…1. Нулевая ось/направление,
NaN/Inf и некорректные числа отвергаются с повторным запросом. Cancel отменяет
текущую операцию. Ошибки чтения OBJ показываются в окне настроек.

## Сборка

Нужны CMake ≥ 3.16, компилятор C++20, Eigen и Qt 6 либо Qt 5 ≥ 5.14
(Core, Gui, Widgets). Зависимости устанавливаются отдельно: git-подмодулей
в текущем репозитории нет, сборка не загружает ничего из сети.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --target 3d-renderer -j 6
./build/bin/3d-renderer
```

В Windows исполняемый файл — `build/bin/3d-renderer.exe`; Qt DLL должны быть
доступны через PATH или размещены рядом с ним. Если CMake не находит Qt/Eigen,
укажите каталог установки через `-DCMAKE_PREFIX_PATH=...`.

Без Qt, только библиотека и её тесты:

```sh
cmake -S . -B build-core -DBUILD_GUI=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-core -j 6
ctest --test-dir build-core --output-on-failure
```

## Проверки

```sh
cmake --build build --config Release -j 6
ctest --test-dir build -C Release --output-on-failure

# AddressSanitizer + UndefinedBehaviorSanitizer (Clang/GCC)
cmake -S . -B build-sanitize -DBUILD_GUI=OFF -DENABLE_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-sanitize -j 6
ctest --test-dir build-sanitize --output-on-failure
```

Проверено локально на macOS: Release-сборка Qt 6, тесты `core_tests` и
`gui_tests`, отдельная Debug-сборка ядра с ASan/UBSan. GUI-тесты используют
платформу Qt `offscreen`: проверяют события, диалоги, сообщения, открытие двух
окон и Exit. Физический захват мыши оконной системой в этом режиме не
проверяется. Windows/Fedora и ветка совместимости Qt 5 здесь не запускались.

## Структура

- `src/core/` — математика, геометрия, OBJ, камера, сцена, освещение, тени,
  растеризация, модель и порт кадров.
- `src/gui/` — два представления и два контроллера ввода.
- `src/app/` — сборка приложения, Qt runtime и граница обработки исключений.
- `tests/` — регрессионные тесты ядра и интерфейса.
- `docs/` — исходные пять PDF программной документации.
- `issues.md` — исходное ревью; сохранено для сопоставления.
- `explain.md` — разбор всех 77 комментариев ревью, объяснение каждого модуля,
  изменения относительно исходного состояния и соответствие документации.

## Границы реализации

OBJ используется как формат геометрии: текстуры и MTL-материалы не рисуются;
`vt` читаются и проверяются, цвет/прозрачность задаются при загрузке. При
отсутствии `vn` нормали вычисляются по общей геометрии вершин. Нужны простые
плоские полигоны с согласованным обходом. Прозрачность — alpha blending
поверхностей, без преломления. Тени жёсткие; рассеянный свет — равномерный
ambient, без глобального освещения. Depth показывает ближайшую поверхность
в оттенках серого `1 / (1 - z_view)`, Normals — нормаль в пространстве камеры.

Размер кадра ограничен 8192 по каждой оси. Производительность зависит от
разрешения, числа треугольников, источников света и прозрачных слоёв; конкретный
FPS не гарантируется. ТЗ не задаёт численного требования к FPS.
